# openfw — an open firmware for the BXE-4-32 (JH7110)

The PowerVR GPU in the JH7110 is driven by firmware running on a small MIPS
core inside the GPU. The upstream Linux `powervr` driver loads it from
`powervr/rogue_36.50.54.182_v1.fw`; Imagination ships that image as a
binary. `openfw/` is a from-scratch, MIT-licensed replacement, built with
an ordinary GCC cross compiler and packed into the same container format.

**Status: milestone M0/M1 (see [docs/firmware.md](../docs/firmware.md)).**
The driver accepts it and keeps it alive: boot handshake, kernel-CCB
processing, MMU cache maintenance, power requests (runtime suspend and
resume), firmware tracing. **It does not execute GPU jobs yet**: a KICK is
consumed and logged, so rendering or compute submissions time out and the
driver resets the GPU. It is a foundation and a test bench, not a usable
replacement yet.

## What has been verified, and how

None of this has run on a VisionFive 2 yet; everything below is emulation
and static checks.

| Check | Tool | Result |
|---|---|---|
| Container + device info accepted by the driver's parser | `tools/pvrfw.py pack --compare` | device info byte-identical to Imagination's; re-packing Imagination's own ELF reproduces their file byte for byte |
| Boot-time register programming | `tools/fwemu --trace-regs`, diffed against the reference | identical writes (MIPS wrapper remap ranges, BIF fault page, MTS event routing, DM-to-thread association) |
| Kernel contract: probe, health check, MMU flush, log type, forced idle, power off, resume | `test_contract.py` (25 checks, same sequence the driver uses) | all pass, as for Imagination's image |
| Wired TLB entries, TLB refill handler, stale-entry fix-up, TLB flush | `test_mmu.py` on Unicorn's TLB-equipped M14Kc model | all pass |
| Boot code never touches unmapped kseg2 | Makefile check on `boot.o` | enforced at build time |

`make test KERNEL=~/linux [REFERENCE=path/to/imagination.fw]` runs the
last three.

## Trying it on the board

```sh
# on the build host (Debian/Ubuntu)
sudo apt install gcc-mipsel-linux-gnu    # tests also need: pip install unicorn
make -C openfw            # -> openfw/rogue_36.50.54.182_v1.fw
# on the board, kernel from kernel/ and nothing using the GPU:
sudo board/openfw-test.sh openfw/rogue_36.50.54.182_v1.fw
```

`prebuilt/rogue_36.50.54.182_v1.fw` is the same build (GCC 12.4, Ubuntu
24.04 `gcc-mipsel-linux-gnu`; the build is reproducible, compare with
`prebuilt/SHA256SUMS`) for boards without a cross compiler at hand.

`openfw-test.sh` saves the installed firmware, installs openfw, reloads
`powervr` with firmware tracing on, checks the probe, cycles runtime
suspend/resume three times, collects `dmesg` and the firmware trace, and
always restores the previous firmware. Please send the log it writes;
it answers the questions emulation cannot (TLB refills on the real core,
MTS interrupt acknowledgement, cache initialisation).

## How it works

```
reset (0xBFC00000, kseg1, temp stack in the boot-data page)
  boot_setup(): CP0 init, caches, EBase 0x9FC02000, vectored interrupts,
                wired TLB entries 0-4 + MIPS-wrapper remap ranges:
                  0  registers 0xCF800000 (4 MiB) -> boot_data.reg_base
                  1,2 page table 0xCF000000      -> boot_data.pt_phys_addr[]
                  3  stack 0xCF600000            -> boot_data.stack_phys_addr
                  4  .bss 0xC0032000             -> from the page table
  clear .bss, jump to fw_main() in kseg2 (first TLB refill)
fw_main(): GPU-side init (as the reference), report ON, firmware_started = 1,
           idle in `wait`
interrupts (start.S save_and_call -> openfw_trap):
  IP3  MTS background task -> drain the kernel CCB, report IDLE
  IP4  MTS interrupt task  -> acknowledge GPU events
  IP2  CP0 timer           -> re-check the kernel CCB (lost-kick safety net)
  TLB refill               -> identity TLB entry from the kernel's page
                              table + remap ranges Random / Random+16
```

Files:

| File | Content |
|---|---|
| `start.S` | reset entry, TLB refill handler, exception and interrupt vectors |
| `boot.c` | processor and MMU setup (runs before kseg2 is mapped) |
| `main.c` | kernel-CCB commands, power requests, tracing, fault reporting |
| `mmu.h`, `mips.h`, `regs.h` | address translation, CP0 helpers, register map |
| `fwif.h` | firmware-interface offsets and trace IDs, generated by `gen_fwif.py` from the kernel headers via `tools/fwemu/layout.json` |
| `device-36.50.54.182.json` | the core's features/BRNs/ERNs (DDK hwdefs + Mesa), packed into the container |
| `link.ld` | fixed section addresses from the kernel's MIPS layout |
| `test_mmu.py`, `test_contract.py` | the checks above |

The design follows what the reference firmware demonstrably does (traced
in `tools/fwemu`): the same wired mappings, remap scheme, boot register
writes and MTS acknowledgement registers. Two deliberate differences: the
page table is mapped uncached so the refill handler always sees the
kernel's latest entries, and handlers do not nest (the reference lets the
interrupt task pre-empt the background task).

## Kernel commands handled

| Command | M0/M1 behaviour |
|---|---|
| `HEALTH_CHECK` | acknowledged |
| `MMUCACHE` | SLC flush+invalidate of MMU data, `BIF_CTRL_INVAL`, firmware TLB flush, sync update |
| `LOGTYPE_UPDATE` | acknowledged (log type is read on every trace) |
| `CLEANUP` | acknowledged, never busy (nothing is ever scheduled) |
| `SLCFLUSHINVAL` | full SLC flush+invalidate |
| `POW` forced idle / cancel | `pow_state` FORCED_IDLE / IDLE, `power_sync` |
| `POW` off | MMU data out of the SLC, page catalogue invalidated, `pow_state` OFF, `power_sync`, core parks in `wait` |
| `POW` dust count | recorded, `power_sync` |
| `KICK`, `COMBINED_GEOM_FRAG_KICK`, others | logged as unknown (forced trace), acknowledged |

Every command gets `CMD_EXECUTED` in its return slot and increments
`kccb_cmds_executed`; the host interrupt is raised once per batch.

## Next: M2 (compute/transfer jobs)

`tools/fwemu --kccb compute` already shows what Imagination's firmware does
for a Vulkan compute dispatch: read the client CCB, check and update the
fences (UFOs), load the CDM registers from the command, kick the compute
data master, take `EVENT_STATUS.COMPUTE_FINISHED`, update fences, report.
Implementing that path is the next step; `--trace-regs` on both images
gives the register sequence to match.
